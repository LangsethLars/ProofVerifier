# AST (Abstract Syntax Tree) Documentation

## Overview

The AST module converts the parse tree generated by the parser into a clean, semantic abstract syntax tree suitable for proof verification. It eliminates syntactic noise (like parentheses, keywords, and punctuation) and organizes the code into a hierarchical structure.

## Architecture

### Files

- **`ASTTypes.h`** - Defines all AST node types
- **`ASTBuilder.h/cpp`** - Converts parse tree to AST
- **`ASTPrinter.h/cpp`** - Pretty-prints the AST for debugging

## AST Node Types

### Base Types

- **`ASTNode`** - Base class for all AST nodes
  - `nodeType`: The specific type of this node
  - `lineNumber`: Source line number for error reporting

- **`DeclNode`** - Top-level declaration
  - `expr`: The expression being declared

- **`ExprNode`** - Base class for all expressions

### Expression Types

#### `IdentNode` - Identifier
```
Represents: x, f, myVar
Fields:
  - name: string
  - lineNumber: int
```

#### `TypeNode` - Type Keyword
```
Represents: Type
Fields:
  - lineNumber: int
```

#### `FunExprNode` - Function Expression
```
Represents: fun x : A => B
Fields:
  - paramName: string
  - paramType: ExprNodePtr
  - body: ExprNodePtr
  - lineNumber: int
```

#### `PiExprNode` - Dependent Function Type
```
Represents: Pi x : A, B
Fields:
  - paramName: string
  - paramType: ExprNodePtr
  - resultType: ExprNodePtr
  - lineNumber: int
```

#### `AppExprNode` - Function Application
```
Represents: f a b c
Fields:
  - function: ExprNodePtr
  - arguments: vector<ExprNodePtr>
  - lineNumber: int
```

## Parse Tree to AST Mapping

The parser generates a flattened parse tree due to "Skip" rules in the grammar. The AST builder handles this by:

1. **Variable ID Encoding**: Parse tree stores variable IDs as `-(varId+1)`
   - Example: `<Decl>` has varId=3, stored as symbolId=-4

2. **Token Representation**: Token nodes store the token sequence number (not token class ID)
   - Access token info via `m_tokenSequence[tokenSeqNo]`

3. **Flattened Structure**: Skip nodes (`<Atom>`, `<AppLoop>`, etc.) are eliminated
   - Children appear directly under their parent

## Usage Example

```cpp
#include "ast/ASTBuilder.h"
#include "ast/ASTPrinter.h"

Proof_Parser parser;
if (parser.lexAndParseFile("script.txt")) {
    ASTBuilder builder(parser);
    auto ast = builder.buildAST();

    if (ast) {
        ASTPrinter printer;
        printer.print(*ast);

        // Process declarations
        for (const auto& decl : ast->declarations) {
            // Type check, elaborate, verify proofs...
        }
    }
}
```


## Key Design Decisions

1. **Smart Pointers**: Uses `std::unique_ptr` for automatic memory management
2. **Minimal Structure**: Only semantic information, no syntactic clutter
3. **Type Safety**: Strong typing via enum classes and inheritance
4. **Line Tracking**: Preserves source locations for error reporting
5. **Application Handling**: Multiple arguments collected into a vector
